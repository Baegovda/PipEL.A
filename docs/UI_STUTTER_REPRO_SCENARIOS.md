- **프로파일:** Python 쪽 병목은 [`PROFILING_AND_TROUBLESHOOTING.md`](PROFILING_AND_TROUBLESHOOTING.md) **§2 cProfile** (`python -m cProfile` 또는 `tools/profile_pipela.ps1`). 저장소에 **내장 UI ms 계측**(`PIPELA_UI_PERF` / `ui_perf_probe`)은 없다(2026-04 제거).
- **지원 로그:** 동작 맥락·예외·하트비트는 `PIPELA_AI_DEBUG` 세션 로그(같은 PROFILING 문서 §3)를 병행한다.

## 시나리오

### S0 — 기준

1. 앱 기동 직후 **20~30초**, 특별한 조작 없이 둔다.  
2. **기록:** 이 상태만으로도 미세 끊김이 있는지(배경/트레이 기동만).

### S1 — 제어창 + 설정(게임/도킹 최소)

1. **제어창**만 사용. (게임·런처 없거나 최소)  
2. **설정** 탭 — 허브에서 패널 **2~3개** 이동, 리스트·스크롤, 숫자 필드(예: LeftClick) 조절.  
3. **터미널 ↔ 설정** 전환 5회 이상.  
4. **기록:** 끊김 있음/없음, **어느 탭·동작**에서 두드러지는지.

### S2 — 제어창 + 앵커(게임/런처 도킹)

1. **이터널시티**(또는 `resolve_dock_anchor_hwnd` 대상) 창을 켠다.  
2. 제어창이 **클라이언트 왼**에 붙은 상태인지 확인.  
3. **제어창 타이틀줄**로 드래그, **게임 창**도 드래그해 위치 이동.  
4. **기록:** 끊김이 **도킹 직후**인지, **드래그 중**인지, **가만 둘 때**인지, **게임 포커스**일 때인지.

### S3 — 상단 스트립 + 게임 투명 오버레이

1. S2를 유지. (타이틀 스트립·`QtGameOverlay`가 켜진 기본 흐름)  
2. 1~2분 **게임 쪽**을 주로 쓰고, 보조 UI는 **클릭 최소**로 둔다.  
3. **기록:** S2 대비 **악화**되는지, **거의 변화 없음**인지.

### S4 — 커서 HUD + 킬 창(사용하는 경우만)

1. S2(또는 S3) + **커서 HUD** 표시, **킬** 플로터 표시(설정·표시 켬).  
2. 킬 창·제어창·게임 사이 **포커스·창** 전환을 여러 번.  
3. **기록:** S2/S3에 비해 **명확히** 나빠지는지.

### S5 — ROI / 리전 미리보기(해당 기능 쓸 때만)

1. **영역 미리보기** 또는 **리전** 관련 창/오버레이를 켜는 흐름.  
2. 켠 상태에서 S1~S2와 비슷하게 조작.  
3. **기록:** 미리보기/오버레이 **끄면** 끊김이 줄어드는지(고주파 타이머·캡처 루프 의심).

## 1단계에서 내릴 결론(예시)

- **S1만 나쁨** → 제어창·설정 **그리기/스타일/이벤트** 쪽 후보.  
- **S2 이후 악화** → **도킹·Win32**·앵커 폴링 쪽 후보.  
- **S3~S4에서만** → **다중 top-level**·`QTimer` 겹침(오버레이·HUD·킬) 후보.  
- **S5에서만/끄면 나아짐** → **리전·미리보기** 타이머·캡처 쪽 후보.
